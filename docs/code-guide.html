DsoftAndroidEmulator: đọc code từ đâu

App WinForms (C# 5, build bằng csc.exe) bọc ngoài Android Emulator chính chủ của Google, thêm map phím và auto click kiểu người thật. Khoảng 2.800 dòng trong 10 file src/*.cs, tất cả cùng namespace DsoftEmu.

1. Mô hình kết nối 2. Thứ tự đọc file 3. Các luồng chính 4. Luồng (thread) 5. File trên đĩa 6. Chi tiết chạm 7. Thuật ngữ

1. Mô hình kết nối

Ba tầng: DsoftEmu.exe (code của bạn) → tiến trình ngoài (emulator.exe, adb.exe) → Android chạy trong máy ảo. Mũi tên xanh là đường đi của một lần chạm (phím hoặc macro → Android). Bấm vào một ô để xem chức năng, cách hoạt động và nó nói chuyện với ô nào; các ô không liên quan sẽ mờ đi.

Bấm vào một ô trong sơ đồ để xem chi tiết.
Ý chính: app không tự giả lập Android. Nó sinh file cấu hình AVD, gọi emulator.exe của Google, rồi dùng adb + scrcpy-server để điều khiển. Toàn bộ giao tiếp với tiến trình ngoài đi qua lớp Proc trong Util.cs.

2. Thứ tự đọc file

Đọc từ trên xuống. Mỗi bước ghi rõ cần hiểu gì trước khi sang bước sau.

  1. Program.cs50 dòng
    Điểm vào Main(): Mutex chặn mở 2 lần → Log.Init → bắt lỗi toàn cục (chỉ ghi log) → Application.Run(new MainForm()).
    Hiểu: app chỉ có 1 form chính, mọi thứ bắt đầu từ constructor của MainForm.
  2. Util.cs222 dòng · nền tảng
    Log (ghi file + event Line để UI hiện), Settings (đọc/ghi settings.ini dạng key=value), FileUtil (xoá/chuyển thư mục), Proc (chạy exe: Run chờ xong, RunBytes lấy nhị phân, Start chạy nền đọc từng dòng).
    Hiểu: Proc.Run/Start là "cửa" duy nhất ra emulator.exe/adb.exe. Đọc kỹ 3 hàm này thì các file sau dễ đọc.
  3. MainForm.cs — chỉ đọc phần nối dâydòng 81–124, 894–953
    Constructor tạo Settings, HostInfo, EmulatorController, TouchService, KeyMapper rồi gắn event: Log.Line, emu.Booted → ConnectInput, emu.Stopped, MacroRunner.Changed, timer 1,5s. Sau đó OnLoaded, ConnectInput, OnClosing.
    Hiểu: ai tạo ai, ai lắng nghe event của ai. Phần dựng giao diện (Build*) để sau.
  4. Emulator.cs322 dòng
    Adb: bọc lệnh adb theo serial. EmulatorController: CreateAvd (tự ghi config.ini, không cần Java/avdmanager) → Start (ghép tham số dòng lệnh) → BootWatch (thread chờ sys.boot_completed=1 hai lần) → OnExit (watchdog tự cold boot tối đa 3 lần) → Stop. Thêm WipeAvd, DeleteAvd, MoveData.
    Hiểu: vòng đời máy ảo, và vì sao event Booted là mốc để bật input.
  5. Input.cs345 dòng · quan trọng nhất
    Screen (poll wm size + hướng xoay mỗi 3s), ITouch với 2 bản cài đặt ScrcpyTouch / AdbTouch, Human (Gauss, log-normal, tam giác), TouchService (Raw, Tap, Hold, Swipe Bezier).
    Hiểu: toạ độ luôn chuẩn hoá 0..1, chỉ đổi sang pixel ở Send(). Xem mục 6 bên dưới.
  6. KeyMapper.cs281 dòng
    Load parse file keymap → Dictionary<vk, Bind>. HookProc (hook bàn phím mức thấp) lọc phím → đẩy vào hàng đợi → thread Worker → Handle (tap/joy/macro/toggle).
    Hiểu: hook chỉ "nuốt" phím khi cửa sổ qemu/emulator đang focus; phím nhả luôn được xử lý để không kẹt chạm.
  7. Macro.cs155 dòng
    Macro.Parse đọc script (loop/tap/dtap/hold/swipe/wait/break). MacroRunner chạy mỗi macro 1 thread, huỷ bằng CancellationToken.
    Hiểu: macro chỉ gọi TouchService, không biết gì về scrcpy/adb.
  8. SdkInstaller.cs296 dòng
    Đọc XML kho Google (repository2-3.xml, sys-img2-3.xml), lọc kênh stable + Windows x64, chọn revision cao nhất, tải zip, kiểm SHA1/SHA256, giải nén, ghi marker .dsoft_rev. Tải thêm scrcpy-server từ GitHub.
    Đọc khi cần sửa phần tải. Không liên quan luồng chạy hằng ngày.
  9. HostInfo.cs + PickerForm.csnhỏ
    HostInfo: WMI đọc phần cứng, ApplyRecommended đề xuất nhân/RAM/độ phân giải. PickerForm: chụp màn hình Android qua adb exec-out screencap, click → toạ độ chuẩn hoá chèn vào editor.
  10. MainForm.cs — phần còn lạiUI
    5 trang: BuildHome (checklist + nút Chạy/Dừng), BuildImages (chọn bản Android), BuildConfig, BuildKeys, BuildMacro. RefreshChecks/RefreshRuntime cập nhật trạng thái. Biến uiOp: 0 rảnh, 1 đang bật, 2 đang dừng.

Ngoài src/: build.bat (csc → bin\DsoftEmu.exe, copy keymaps/macros), pack.bat (đóng gói bản lite/offline vào dist\), keymaps/default.txt và macros/sample.txt có chú thích cú pháp ngay trong file.

3. Các luồng chính

Bấm để mở từng luồng. Mỗi bước ghi file và hàm.

A. Mở app
  1. Program.Main → Mutex DsoftEmu_single_instance → Log.Init("logs") Program.cs:30
  2. new MainForm(): đọc settings.ini; HostInfo.Detect(); lần đầu (chưa có key Cores) thì ApplyRecommended + lưu MainForm.cs:81
  3. Tạo EmulatorController, KeyMapper(touch) (constructor khởi thread Worker), gán mapper.ToggleMacro = ToggleMacro
  4. Dựng 5 trang, gắn event (Log.Line, emu.Booted, emu.Stopped, timer, kéo thả APK)
  5. OnLoaded: nạp keymap → mapper.Install() (cài hook) → refresh UI → CheckAccel() (emulator -accel-check) → bật timer → nếu Android đã chạy sẵn từ trước thì ConnectInput() luôn MainForm.cs:926
B. Bấm ▶ Chạy → Android boot → input sẵn sàng
  1. StartEmu(cold): SaveUi(), kiểm tra có emulator.exe + image, uiOp=1, gọi Bg(...) (Task.Run) MainForm.cs:495
  2. emu.Start(cold) → CreateAvd() ghi lại avd\<Tên>.avd\config.ini theo cấu hình hiện tại (không đụng dữ liệu) Emulator.cs:209, 155
  3. adb start-server, ghép tham số: -avd -port -gpu -cores -memory + tuỳ chọn (-wipe-data nếu có file .dsoft_wipe, -no-snapshot-load nếu cold boot, -feature -Vulkan...)
  4. Proc.Start(emulator.exe): mọi dòng output ghi vào logs\emulator.log, dòng ERROR/FATAL đẩy lên log UI. Gắn proc.Exited += OnExit
  5. Thread BootWatch: sau 6s đặt ưu tiên AboveNormal cho qemu-system*; poll mỗi 2s tối đa 400s: adb devices + getprop sys.boot_completed, cần đạt 2 lần cách 3s Emulator.cs:254
  6. Bắn event Booted → MainForm chạy ConnectInput() trên Task MainForm.cs:115, 894
  7. ConnectInput: touch.Scr.Attach(adb) (bắt đầu poll kích thước màn hình) → thử ScrcpyTouch.Start(); lỗi hoặc thiếu file jar thì dùng AdbTouch → gán touch.Inj
  8. ScrcpyTouch.Start: adb push jar → adb forward tcp:PORT localabstract:scrcpy_ID → adb shell app_process ... Server 2.7 video=false audio=false control=true ... → thử kết nối TCP tới khi đọc được "dummy byte" (≤ 6s) → thread Drain giữ kết nối Input.cs:78
C. Nhấn 1 phím trong cửa sổ giả lập → chạm trên Android
  1. Windows gọi KeyMapper.HookProc. Bỏ qua phím do phần mềm khác bơm (cờ 0x10) KeyMapper.cs:126
  2. Phím có trong byVk? Nếu là phím nhấn: chỉ xử lý khi map đang bật (hoặc là phím toggle) và EmuForeground() = cửa sổ trước mặt thuộc tiến trình qemu-system*/emulator (có cache theo pid)
  3. Đẩy (vk, down/up) vào BlockingCollection, trả về 1 để nuốt phím (Android không nhận phím đó)
  4. Thread Worker lấy ra → Handle: bỏ auto-repeat; theo loại bind:
    • tap: nhấn → Jittered (lệch ngẫu nhiên bán kính r) → Raw(0=down); nhả → Raw(1=up)
    • joy: tính hướng từ 4 phím → chạm giữ ở tâm, kéo tới tâm + hướng × bán kính qua 3 bước Raw(2=move); thả hết phím → Raw(1)
    • macro: gọi ToggleMacro(tên) của MainForm
    • toggle: đảo Enabled, tắt thì nhả hết chạm
  5. TouchService.Raw kẹp toạ độ 0..1 → Inj.Send(action, id, nx, ny)
  6. ScrcpyTouch.Send: đổi sang pixel theo Screen.W/H (làm tròn bội số 8), đóng gói 32 byte, ghi socket (có lock). AdbTouch thì gom down→up rồi gửi input tap hoặc input swipe qua 1 phiên adb shell
D. Chạy macro (auto click)
  1. Nút ▶ ở trang Auto click hoặc phím macro trong keymap → MainForm.ToggleMacro(name): đang chạy thì dừng, chưa chạy thì đọc macros\name.txt MainForm.cs:880
  2. Macro.Parse → danh sách bước + Loop, Break Macro.cs:31
  3. MacroRunner.Start: tạo CancellationTokenSource, cấp 1 id chạm riêng (từ 2001), mở thread mới
  4. Mỗi vòng: chờ touch.Ready → chạy từng bước bằng TouchService.Tap/Hold/Swipe; wait có 3% chần chừ thêm; cuối vòng có pct% nghỉ dài
  5. Dừng: cts.Cancel() → TouchService.Wait ném OperationCanceledException → finally trong Hold/Swipe luôn gửi Raw(1=up) nên không kẹt ngón
E. Emulator crash → tự khởi động lại
  1. proc.Exited → OnExit lấy exit code Emulator.cs:292
  2. Nếu không phải do bấm Dừng (stopping=false), mã ≠ 0, bật AutoRestart, chưa quá 3 lần → chờ 3s → Start(cold:true)
  3. Ngược lại bắn event Stopped → MainForm đặt androidReady=false, refresh UI. Bộ đếm autoRestarts về 0 khi boot thành công
F. Bấm ■ Dừng / đóng app
  1. StopEmu: uiOp=2 → emu.Stop(): stopping=true, adb emu kill, chờ tối đa 25s, quá thì taskkill /T /F Emulator.cs:310
  2. Đóng form (OnClosing): hỏi tắt giả lập không → dừng timer, dừng mọi macro, gỡ hook, đóng kết nối input MainForm.cs:940
G. Tải SDK + bản Android
  1. InstallTools: đọc repository2-3.xml (dự phòng 2-1) → Parse lọc stable + windows/x64 → Best chọn rev cao nhất cho platform-tools, emulator SdkInstaller.cs:77
  2. InstallZip: marker .dsoft_rev trùng URL thì bỏ qua; không thì tải vào sdk\.tmp, kiểm checksum, giải nén, chuyển vào chỗ đích
  3. Tải scrcpy-server-v2.7 từ GitHub (không có checksum)
  4. Trang Bản Android: ListImages gộp danh sách online (API ≥ 28) + bản đã cài trên đĩa (dùng được khi mất mạng); InstallImage dùng lại InstallZip

4. Các luồng (thread) đang chạy

Code chạy song song nhiều chỗ. Muốn đụng UI từ thread khác phải đi qua MainForm.UI(...) (BeginInvoke).

ThreadTạo ở đâuLàm gì
UIApplication.RunForm, timer 1,5s RefreshRuntime, và callback HookProc (hook được cài trên thread này nên Windows gọi lại trên thread này)
TaskMainForm.Bg(), Task.RunViệc nặng: Start/Stop emulator, tải SDK, cài APK, ConnectInput. Xong gọi UI(RefreshAll)
BootWatchEmulatorController.StartChờ boot xong, bắn Booted
Screen pollScreen.AttachMỗi 3s đọc kích thước + hướng xoay (chỉ tạo 1 lần)
KeyMapper.Workerconstructor KeyMapperXử lý hàng đợi phím, gửi chạm. Ưu tiên AboveNormal
macro <tên>MacroRunner.Start1 thread mỗi macro đang chạy
DrainScrcpyTouch.StartĐọc bỏ dữ liệu từ socket; socket đóng → alive=false
ThreadPoolProc.StartCallback từng dòng output của emulator/scrcpy, proc.Exited → OnExit

Chỗ đồng bộ: lock(touch) trong ConnectInput, lock(lk) khi ghi socket scrcpy, lock(running) trong MacroRunner, volatile cho Inj, IsBooted, uiOp, androidReady.

6. Chi tiết hệ chạm

Quy ước

  • Toạ độ chuẩn hoá 0..1 ở mọi tầng trên (keymap, macro, TouchService). Chỉ Send() mới đổi sang pixel.
  • Bán kính r tính theo cạnh ngắn màn hình; TouchService.Radius đổi ra rx, ry cho từng trục.
  • action: 0 = down, 1 = up, 2 = move.
  • id ngón tay: mỗi bind keymap một id từ 10; mỗi lần chạy macro một id từ 2001. Khác id → đa điểm thật (chạy WASD + bấm nút cùng lúc).
  • Human: lệch vị trí kiểu Gauss (dày ở tâm), thời gian nhấn log-normal quanh 85ms (45–180), chờ dạng tam giác Between(a,b), swipe theo Bezier bậc 2 + ease in-out.

Gói chạm gửi scrcpy-server (32 byte, big-endian)

OffsetByteNội dung
01type = 2 (INJECT_TOUCH_EVENT)
11action
28pointer id
104x pixel
144y pixel
182width màn hình
202height màn hình
222pressure (0 khi up, 0xFFFF còn lại)
244actionButton = 0

Bố cục này gắn với scrcpy 2.7 (SdkInstaller.ScrcpyVersion). Đổi phiên bản scrcpy thì phải kiểm lại bố cục gói tin.

7. Thuật ngữ

TừNghĩa trong project này
AVDAndroid Virtual Device: thư mục .avd chứa cấu hình + ổ dữ liệu của 1 máy ảo.
System imageBộ file hệ điều hành Android (system.img...) theo API + tag + abi. Chỉ đọc, dùng chung.
WHPXWindows Hypervisor Platform: tăng tốc phần cứng cho QEMU khi Hyper-V đang bật. Kiểm bằng emulator -accel-check.
adb / adbdCông cụ debug Android: adb.exe ở Windows nói chuyện với adbd trong Android.
scrcpy-serverFile jar chạy trong Android bằng app_process; ở đây chỉ dùng kênh điều khiển để bơm chạm nhanh, đa điểm.
Quick boot / Cold bootQuick boot: lưu snapshot RAM khi tắt, mở lại nhanh. Cold boot: bỏ qua snapshot, boot từ đầu (-no-snapshot-load).
Xoá trắng (wipe)Xoá userdata/cache/snapshot trong .avd, đặt cờ .dsoft_wipe để lần chạy tới thêm -wipe-data.
WH_KEYBOARD_LLHook bàn phím mức thấp toàn hệ thống (id 13) của Windows, dùng trong KeyMapper.

Gỡ lỗi: không có debugger vì build bằng csc. Xem bin\logs\app.log (mọi Log.I) và bin\logs\emulator.log (output gốc của emulator).
